# Threat model

This table lists each threat from the brief (§14), what the code does about it, and what it does not do yet. Every row was checked against the code on 2026-11-20. Paths are relative to the repo root.

## Controls

| Threat                                    | Control in the code                                                                                                                                                                                                                                                                                                                                                                                                                               | Status  | Gaps                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **The oracle lies about the sea**         | Two models must both exceed the threshold (`packages/shared/src/trigger.ts`). Under 10 valid hours from either model gives `indisponible`, which never pays. The oracle commits to its nonce `R` the evening before, so a second outcome would reveal its key (`recoverKey` in `packages/oracle/src/crypto.ts`). Raw responses are hashed into the signed attestation, and the browser recomputes the hashes, the window maximum and the outcome. | Done    | Both models come through one provider (Open-Meteo). The browser re-hashes the server's archived copy: this proves the copy matches what was signed, not that Open-Meteo sent it. A missed evening commitment can still be made until 05:15, and the verifier only checks that it predates the 06:00 window. |
| **The oracle colludes with the payer**    | The oracle key cannot move money, and the pool key cannot sign facts. Anyone can re-check every payout against a signed `danger` attestation.                                                                                                                                                                                                                                                                                                     | Done    | A council co-signer (2-of-3 attestations) is on the roadmap.                                                                                                                                                                                                                                                |
| **Oracle key stolen**                     | Five separate secrets, which the config refuses to start with if any two are equal (`apps/server/src/config.ts`). Fresh CSPRNG nonce per event, sealed with AES-256-GCM, deleted in the same transaction as the attestation (`apps/server/src/oracle/jobs.ts`).                                                                                                                                                                                   | Partial | The nonce-sealing key is derived from the oracle key, so it protects a leaked database or backup, not a leaked server. **Key rotation is not implemented**: the verifier compares against the current public key, so after a rotation old attestations would fail.                                          |
| **Pool wallet drained**                   | The app enforces `DAILY_PAYOUT_CAP_SATS` when planning payouts, net of what was already paid that day, and again when the council retries a failed payout. Payouts go only to the Lightning address stored at enrolment, and the invoice amount is checked before paying.                                                                                                                                                                         | Partial | The council can change the cap. The wallet-side NWC budget must be set in the wallet; the app cannot enforce it (the live test wallet has none).                                                                                                                                                            |
| **Double payout**                         | Unique index on `(policy, attestation)` and on `payment_hash`; one payout run per attestation; the invoice is stored before paying, and the wallet is asked whether it was paid before any resend. A new invoice is requested only after the old one expires.                                                                                                                                                                                     | Done    | —                                                                                                                                                                                                                                                                                                           |
| **Buying cover after seeing the storm**   | 72 h waiting period from the premium payment (`WAITING_HOURS`, `apps/server/src/pool/policies.ts`).                                                                                                                                                                                                                                                                                                                                               | Done    | The council can set 0–720 h. Renewing while still covered skips the wait, by design.                                                                                                                                                                                                                        |
| **Ghost crews**                           | Crews are created only from the council dashboard (session + CSRF) or by the demo seed command. No public route creates crews.                                                                                                                                                                                                                                                                                                                    | Done    | —                                                                                                                                                                                                                                                                                                           |
| **Personal data leaks**                   | Phone and Lightning address sealed at rest with a separate PII key. Policies on Nostr carry only a salted hash commitment. Log redaction, plus a test that runs a full payout, SMS, USSD and status-page flow and greps the logs for phone numbers, addresses and tokens (`apps/server/src/lib/security.test.ts`).                                                                                                                                | Done    | Redaction covers known field names; the rest relies on the "never log personal data" rule. Crew pseudonyms are public.                                                                                                                                                                                      |
| **Data outage or bad data**               | `indisponible` outcome; minimum 10 valid hours per model; an all-zero window counts as no data; council alert on `indisponible`.                                                                                                                                                                                                                                                                                                                  | Done    | —                                                                                                                                                                                                                                                                                                           |
| **Pool too small for a fleet-wide storm** | Pro-rata payouts with the shortfall recorded on the run; public coverage ratio against the worst backtest week (`/api/pool`, home page).                                                                                                                                                                                                                                                                                                          | Done    | The reserve floor is a manual setting (default 0).                                                                                                                                                                                                                                                          |
| **Replay confused with live**             | Separate demo oracle key, `ndox-replay` tag, _Rejeu_ and _Simulé_ badges; replays pay from a separate simulated account, never the live pool.                                                                                                                                                                                                                                                                                                     | Done    | —                                                                                                                                                                                                                                                                                                           |
| **Council account takeover**              | scrypt password hash, constant-time compare; httpOnly, SameSite=Strict cookie scoped to `/api/admin` (Secure on https); HMAC CSRF token; Origin check; login limited to 5 tries per 15 min per IP and 100 overall.                                                                                                                                                                                                                                | Done    | A request with no Origin header is allowed but still needs the CSRF token. Sessions are kept in memory (12 h) and end on restart.                                                                                                                                                                           |
| **Web attacks**                           | CSP (`script-src 'self'`, `frame-ancestors 'none'`), HSTS, nosniff, `X-Frame-Options: DENY`; zod validation on every input; rate limits on the explainer, crew status, USSD and sponsor invoices; `TRUST_PROXY` hop count so a forged `X-Forwarded-For` can't dodge limits.                                                                                                                                                                       | Done    | Rate limits are in memory, one process.                                                                                                                                                                                                                                                                     |
| **AI misleads people**                    | Bulletin: written only from signed facts; any number in the model's text that is not a fact replaces it with a template, and the page says which wrote it. Explainer: given only the published rules, with the question passed as tagged data. The model never touches money, keys or crew data.                                                                                                                                                  | Partial | The explainer's "answer only from the rules" is enforced by the prompt; its output check looks only for "Je ne sais pas" and length, not for numbers.                                                                                                                                                       |
| **Losing the database**                   | Daily SQLite online backup, last 7 kept; health-check ping after each tick, `/fail` on errors (when `HEALTHCHECK_URL` is set).                                                                                                                                                                                                                                                                                                                    | Partial | Backups sit on the same volume, unencrypted, with no off-site copy.                                                                                                                                                                                                                                         |

## Tests

- **Equivocation:** `packages/oracle/src/crypto.test.ts` ("signing two outcomes with the same nonce leaks the oracle key"), `apps/server/src/api/verifier.test.ts` (the browser demo recovers the throwaway key), `apps/server/src/oracle/jobs.test.ts` ("deletes the nonce in the same step and never signs twice").
- **Payout cap and idempotency:** `apps/server/src/payouts/engine.test.ts` (cap across sites; crash before and after sending; running the engine twice pays nothing more), `packages/shared/src/money.test.ts`.
- **Personal data:** `apps/server/src/lib/security.test.ts` (log grep), `apps/server/src/pool/pool.test.ts`, `apps/server/src/lib/box.test.ts`.
- **Council account:** `apps/server/src/api/admin.test.ts` (hardened cookie; no session, CSRF or wrong origin refused; login rate limit), `apps/server/src/lib/password.test.ts`.

## Honest limits

- **Basis risk:** a grid-cell forecast is not the beach. At 2.5 m, the live rule matches 2 of 25 press-reported ANACIM alert days (see the README).
- **One data provider** for both models.
- **Custody:** one Lightning wallet held by the server. An on-chain DLC is on the roadmap.
- **Regulation:** framed as the council's own mutual fund; scaling needs a licensed partner in the CIMA zone.
- **Cash-out** to mobile money is simulated.
